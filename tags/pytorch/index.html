从 GEE 到 PyTorch：一个遥感人的 AI 自学路径

起点：GEE 打开了新世界 读研的时候，导师扔过来一个需求：用遥感数据做作物种植结构提取。传统做法是 ENVI + 人工目视解译，一张图要判读大半天。偶然间发现了 Google Earth Engine（GEE），一个跑在云端的遥感分析平台，几十行 JavaScript 就能处理 TB 级的影像数据。 GEE 最大的好处是不用下载数据。Landsat、Sentinel、MODIS 全在云端，直接调 API 做裁剪、合成、分类。第一次用它跑完一个 NDVI 时序分析，从写代码到出结果只花了 20 分钟，而之前光下载数据就要半天。 但 GEE 有两个硬伤：一是网络问题，国内访问时好时坏；二是算力受限，复杂模型跑不动。这让我开始思考——能不能把流程搬到本地？ 转折：Python 是连接一切的胶水 GEE 的 Python 版 API（geemap）是个过渡方案。用 geemap 可以在 Jupyter Notebook 里交互式地调用 GEE，同时用本地 Python 做后处理。 慢慢地，我的工具链变成了： 数据获取：GEE API + sentinelsat（下载 Sentinel 数据） 预处理：rasterio + GDAL（裁剪、重投影、波段计算） 特征提取：scikit-learn（PCA、特征选择） 可视化：matplotlib + folium（地图可视化） 这个阶段最大的收获是理解了数据流的概念：遥感分析本质上就是一条数据管道，从原始影像到最终产品，每一步都是输入 → 处理 → 输出。 跃迁：PyTorch 和深度学习 转折点是导师说了一句：“现在做变化检测，深度学习效果比传统方法好很多。” 于是开始啃 PyTorch。说实话，入门曲线很陡。之前写 Python 是"能跑就行"，PyTorch 要求你理解张量运算、自动求导、GPU 加速这些概念。 我的学习路径是： 先跑通官方教程：PyTorch 的 60 分钟入门教程，逐行理解 复现一篇论文：找了一篇用 U-Net 做建筑物提取的论文，从数据准备到模型训练完整走一遍 改造到自己的场景：把 U-Net 换成 DeepLabV3+，数据换成遥感影像，做大棚检测 踩过的坑不少。最大的一个坑是数据预处理——遥感影像动辄几 GB，不能直接塞进 DataLoader。后来学会了用滑动窗口切片 + 数据集分块（torch.utils.data.Dataset 自定义）的方式解决。 ...
