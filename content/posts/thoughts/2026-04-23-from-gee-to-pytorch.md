## 起点：GEE 打开了新世界

读研的时候，导师扔过来一个需求：用遥感数据做作物种植结构提取。传统做法是 ENVI + 人工目视解译，一张图要判读大半天。偶然间发现了 Google Earth Engine（GEE），一个跑在云端的遥感分析平台，几十行 JavaScript 就能处理 TB 级的影像数据。

GEE 最大的好处是**不用下载数据**。Landsat、Sentinel、MODIS 全在云端，直接调 API 做裁剪、合成、分类。第一次用它跑完一个 NDVI 时序分析，从写代码到出结果只花了 20 分钟，而之前光下载数据就要半天。

但 GEE 有两个硬伤：一是网络问题，国内访问时好时坏；二是算力受限，复杂模型跑不动。这让我开始思考——能不能把流程搬到本地？

## 转折：Python 是连接一切的胶水

GEE 的 Python 版 API（`geemap`）是个过渡方案。用 `geemap` 可以在 Jupyter Notebook 里交互式地调用 GEE，同时用本地 Python 做后处理。

慢慢地，我的工具链变成了：

- **数据获取**：GEE API + `sentinelsat`（下载 Sentinel 数据）
- **预处理**：`rasterio` + `GDAL`（裁剪、重投影、波段计算）
- **特征提取**：`scikit-learn`（PCA、特征选择）
- **可视化**：`matplotlib` + `folium`（地图可视化）

这个阶段最大的收获是理解了**数据流**的概念：遥感分析本质上就是一条数据管道，从原始影像到最终产品，每一步都是输入 → 处理 → 输出。

## 跃迁：PyTorch 和深度学习

转折点是导师说了一句："现在做变化检测，深度学习效果比传统方法好很多。"

于是开始啃 PyTorch。说实话，入门曲线很陡。之前写 Python 是"能跑就行"，PyTorch 要求你理解张量运算、自动求导、GPU 加速这些概念。

我的学习路径是：

1. **先跑通官方教程**：PyTorch 的 60 分钟入门教程，逐行理解
2. **复现一篇论文**：找了一篇用 U-Net 做建筑物提取的论文，从数据准备到模型训练完整走一遍
3. **改造到自己的场景**：把 U-Net 换成 DeepLabV3+，数据换成遥感影像，做大棚检测

踩过的坑不少。最大的一个坑是**数据预处理**——遥感影像动辄几 GB，不能直接塞进 DataLoader。后来学会了用滑动窗口切片 + 数据集分块（`torch.utils.data.Dataset` 自定义）的方式解决。

另一个坑是**类别不平衡**。大棚在影像中占比很小，正负样本比可能 1:100。用 Focal Loss + 过采样才勉强解决。

## 延伸：从模型到系统

模型训练好了，怎么让甲方用？不可能让人家装 PyTorch 环境。

这就逼着我学了后端开发。FastAPI 上手很快，Python 写的和模型推理无缝衔接。前端选了 Vue3 + DataV（甲方喜欢大屏）。Docker 打包部署，一套流程下来，从"论文里的模型"变成了"浏览器里能用的系统"。

技术栈最终定型：

```
遥感数据 → Python 处理 → PyTorch 模型 → FastAPI 接口 → Vue3 前端
```

## 经验总结

几条真心话：

1. **别纠结工具，先解决问题**。GEE、Python、PyTorch 都是工具，关键是理解业务需求
2. **遥感 + AI 的核心不是模型，是数据**。标注质量、预处理流程、数据增强，这些比换模型架构重要得多
3. **全栈能力是加分项**。遥感人如果只会 ENVI + ArcGIS，天花板很低。能写代码、能搭系统，路会宽很多
4. **保持手感**。代码和遥感分析都是手艺活，停一个月就生疏

这条路不难走，但需要持续动手。每解决一个实际问题，技术就长进一层。
